# 排班修复与候选选择 · v0.0.4

九张表中，505、506、507 的可行候选能比工具默认方案多满足偏好。模型选中了这些候选，共多满足 7 项偏好，只多改 1 个班次。其余六张表的默认方案已经达到候选内最高偏好数。**本轮三项偏好都能直接计分，九张表用规则排序即可取得相同的偏好数和改动数。** 自由表达且难以编码的偏好仍需另做实验。

## 比较方法

每张表保留原人员、房间、班长和全部班次，允许在 168 小时内移动开工时间。硬约束覆盖人员和房间重叠、最短休息、连续工作时长。三个等权偏好为 A 保留原开始时间、B 在 06:00 至 12:00 前开工、C 在 12:00 至 18:00 前开工，小时按 24 取模。成功交付要求完整班表通过独立逐小时检查。

专家按四种顺序尝试插入班次，默认选改动班次最少、其次累计移动时长最短的候选。自由调班圆桌允许模型修改开始时间，再由专家复核。受限选择圆桌先验证所有候选，模型只能返回候选编号，回复失败或编号无效时交付编号 0。规则排序在同一候选集合内依次按偏好数降序、改动班次数升序、编号升序选择。

## 逐表结果

单元格为成功交付的「满足偏好数 / 改动班次数」。每张表最多满足 3 项。单模型在九张表均未成功；失败提案的改动数与原始偏好计数保存在逐表 CSV。

## 复现

在仓库根目录使用 Python 3.11+，启动本机 Ollama 并准备好 qwen3.5:9b。两条实验命令分别使用新的输出目录。它们使用同一批种子 501–509，各输出逐表 CSV、SQLite 账本和本地调用证据。第一条执行 18 次模型推理，第二条执行 9 次。模型环境可能影响选择和耗时。

```bash
python -m examples.repair_benchmark reports/repair-repro --model qwen3.5:9b
python -m examples.select_repair reports/select-repro --model qwen3.5:9b
python -m unittest discover -s tests -p test_repair.py -v
```

最后一条命令可离线重算九张表的规则排序，并检查回退和失败提案的记账。
