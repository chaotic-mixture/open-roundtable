# 路线图

路线可根据新证据调整，不把原型局限固化成愿景限制。

## Phase 0 — 已实现：来源与可执行状态内核

验收：原始讨论有角色与来源；章程不混入助手未采纳建议；本地议题可持久化、受限预算、暂停恢复、程序性多数票、反馈标签；合成CLI可复跑；测试真实通过；私有参考默认排除公开发布。

## Phase 1 — 真实能力会诊

围绕一个低风险可验证任务接真实专家工具与模型；显示输入、输出、实际费用/资源及验证结果。比较单模型、单工具、协作三种方式。不以合成消息证明提升。

## Phase 2 — 双终端与重访

独立节点发现/收发、恢复离线任务、成员本地特征索引、匿名目标与权限。先验证互操作，再决定是否采用完整通信框架；本地、云端、混合均保留。

## Phase 3 — 圆桌作为成员

实现子圆桌实际参与与多层资源核算；区分活圆桌与历史制品。检验递归是否提升任务完成能力，而非仅延长讨论。

## Phase 4 — 贡献与资源交换

用明确、允许供给的资源试验贡献与消费账本、实践反馈、质量信号、冷启动和反刷。核验每种服务权益；区块链和价值换算根据实际结算需求选择。不预先发行货币。

## Phase 5 — 开放网络与自改进实验

扩大异构参与、支持人类角色；元议题先产出可比较的改进提案并检验实际效果，再决定何种改动可以在何种授权下应用。涌现只作为待测现象，不作交付承诺。

## 主分支验证进度（2026-11-23）

下表覆盖 v0.0.6 及此后在主分支上实现的功能。版本标签的验收范围见 [v0.0.6 验收摘要](V0.0.6.md)。

| 阶段 | 已有证据 | 仍需验证 |
|---|---|---|
| 0 状态内核 | 合成议题可持久化，独立回读检查余额、成员、消息、表决、反馈和标签。[核验程序](../tests/verify_core.py) | 当前使用本地 SQLite 与整数测试 credits。 |
| 1 能力会诊 | 真实模型与排班专家完成检查、修复和偏好选择；九表对照记录了规则与模型各自的收益。[逐表结果](../examples/preference_results.md) | 新偏好类型与真实业务排班中的泛化效果。 |
| 2 节点协作 | 同机双进程发现、授权、双向发送、两种断线窗口恢复、回执与扣费去重、离线重访有回归覆盖。[节点回归](../tests/test_peers.py) | 跨物理主机身份认证、加密与匿名目标；模型回执落盘前中断的独立核对。 |

| 4 资源交换 | 两端可核对消费与贡献，限制受理次数，消费方凭回执记录私有实践反馈。[节点命令](../examples/peer_node.py) | 跨身份防刷，以及不同资源供给者之间的权益核验。 |
| 5 改进实验 | 元议题预先登记通过条件，再在九张新表上比较排序策略。偏好分从 32/63 增至 44/63，两组全部通过硬约束。[复现实验](../examples/meta_consult.py) | 人类参与的实际决策流程，以及经授权应用和撤回改动。 |
