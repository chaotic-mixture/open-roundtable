# 路线图

路线可根据新证据调整，不把原型局限固化成愿景限制。

## Phase 0 — 当前：来源与可执行状态内核

验收：原始讨论有角色与来源；章程不混入助手未采纳建议；本地议题可持久化、受限预算、暂停恢复、程序性多数票、反馈标签；合成CLI可复跑；测试真实通过；私有参考默认排除公开发布。

## Phase 1 — 真实能力会诊

围绕一个低风险可验证任务接真实专家工具与模型；显示输入、输出、实际费用/资源及验证结果。比较单模型、单工具、协作三种方式。不以合成消息证明提升。

## Phase 2 — 双终端与重访

独立节点发现/收发、恢复离线任务、成员本地特征索引、匿名目标与权限。先验证互操作，再决定是否采用完整通信框架；本地、云端、混合均保留。

## Phase 3 — 圆桌作为成员

实现子圆桌实际参与与多层资源核算；区分活圆桌与历史制品。检验递归是否提升任务完成能力，而非仅延长讨论。

## Phase 4 — 贡献与资源交换

用明确、允许供给的资源试验贡献与消费账本、实践反馈、质量信号、冷启动和反刷。核验每种服务权益；区块链和价值换算根据实际结算需求选择。不预先发行货币。

## Phase 5 — 开放网络与自改进实验

扩大异构参与、支持人类角色；元议题先产出可比较的改进提案并检验实际效果，再决定何种改动可以在何种授权下应用。涌现只作为待测现象，不作交付承诺。

## 公开发布检查

独立测试、许可证范围、无私有会话/凭证、干净白名单快照、依赖与素材血缘、准确能力说明。源码发布流程见 [公开发布清单](PUBLIC_RELEASE_CHECKLIST.md)。
