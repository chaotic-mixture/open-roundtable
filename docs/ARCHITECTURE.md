# 架构分层与实施边界

## 目标形态（非已实现宣称）

```text
本地 Agent / 人类议主
       │ 议题、背景、资源预算
       ▼
可插件扩展的圆桌环境 ─── 成员：模型 / 专家系统 / 人类 / 其他圆桌
       │                          │
       │                   专业分析、工具结果、提案、异议
       ▼                          │
讨论与程序决议 ◀─────────────────┘
       │
实践 / 结果反馈 / 特征标记
       │
贡献与资源使用记录 → 后续会诊与资源交换
       │
极低优先级元议题 → 改进候选（如何应用另定）
```

## Phase 0

持久化层记录议题、成员、讨论消息、票、预算、反馈和标签。API 与 CLI 只操作本地数据库；不是公网服务，没有自动工具执行。圆桌型成员仅保留类型/来源，不把登记动作称作递归协作已经实现。反馈和标签只记录，不自动成为事实、信誉或收入。

## 可替换边界

1. ParticipantAdapter：输入输出适配；内部可以是 LLM、程序、人或子圆桌。接口的最终错误/流式/状态契约仍待验证。
2. DeliberationPolicy：成员名册、轮次、提案、投票和结束规则。多数票策略只是初始参考。
3. ResourceProvider / AccountingPolicy：测试预算与真实资源背书分离；后续价格基准单独适配。
4. Transport：本地、云端和混合部署的通信；MCP/A2A 是候选，不要求所有内部组件强行通过网络。
5. FeedbackStore / TagIndex：保存实践观测与可重访线索；主张与验证状态分开。
6. RoundtableAdapter：可把活的圆桌作为一个成员；不默认将圆桌压缩成只读结论。
7. MetaIssueScheduler：最低优先级、可让位于主任务；当前可记录 meta / lowest 元议题提案；没有后台调度或自修改实现。

## 两种递归

- 组织递归：圆桌参与圆桌，属于运行关系。
- 改进递归：圆桌评议项目自身，属于更新关系。

二者必须分别预算、观测和验证。当前没有为整个网络写死无环结构，也没有承诺可无界执行。

## Phase 0 不能保证

没有身份鉴权、多租户隔离、匿名性保证、恶意成员防护、生产级并发可靠性或真实模型质量评测。一个自称 expert 的 kind 字段不能证明专业资质；数据库中给出的人类身份也未经认证。
