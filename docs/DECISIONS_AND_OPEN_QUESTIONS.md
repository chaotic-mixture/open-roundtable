# 决定、候选与未决问题

## 记录类型

- USER_ORIGIN：原始构想已保留；不等于已验证或每个参数已冻结。
- BOOTSTRAP_SCOPE：本轮可逆的工程取舍。
- OPEN：后续需讨论/实验，不让原型默认值偷偷成为正式协议。
- ASSISTANT_PROPOSAL：助手建议，未经明确采纳不得升级为项目定义。

## 本轮工程取舍（BOOTSTRAP_SCOPE）

- 独立目录、标准库 Python + SQLite；不绑定特定模型提供商。
- 离线 API/CLI 先验证状态与预算，不实现网络和支付。
- 演示是合成预置发言，不是模型实际讨论或性能基准。
- 讨论开始后固定名册，严格过半是可替换示例政策；一个成员不能重复计票。
- 测试 credits 是整数计数，不是模型 token、货币或链上代币；不自动按时间铸造可兑付额度。
- 元议题可记录为 meta / lowest 数据提案；无后台调度、自改代码或全局设置写入。
- MIT 作为原始代码/文档的初始许可；原始对话、第三方内容和运行数据不在其再授权范围内。
- 本地建仓不等于公开发布。所有对外发布另行审查。

## 下一轮优先讨论（OPEN）

1. **会诊触发**：没有把握的可操作指标；用户指定/验证失败/预算策略如何并用。
2. **轮次与对象**：对哪个提案投票；动态进出成员如何确定分母；修改提案后旧票是否失效。
3. **拒绝与分歧**：不达成共识时继续、暂停或结束的规则；异议如何进入后续实践。
4. **输出契约**：直接接规则系统的结果，还是经代理发言；不给非语言专家强加聊天人格。
5. **结果反馈**：如何区分建议质量、执行错误、环境变化；反馈可否质证；并非每个领域都有即时真值。
6. **供给与计价**：推理 token、GPU 时间、服务权益、账户配额、经济信用分开；不假定同 token 等能力。
7. **贡献公式**：原始供给减消费的启发保留，但反刷、冷启动、质量评估与负余额未定。
8. **订阅共享**：未来逐服务核验授权与条款，不能把某人的订阅余额当通用可转售资产；当前无共享代码。
9. **递归圆桌**：活的子圆桌、历史制品代理或二者并存；内部开销/投票/来源相关性如何核算。
10. **暂停续作**：可长期等待不等于模型上下文无限增长；成员版本、证据失效与重开条件未定。
11. **身份与匿名**：对其他成员、对中继、对结算方的匿名目标分别定义；不预设强制实名或无审计。
12. **链上方案**：记账/锚定/支付/治理分别评估，当前不选择链或发行资产。
13. **低优先级自改进**：如何记录改进提案、测试、效果反馈和权限；不把无人维护当可用性前提。

## 下一阶段默认建议

先选一个有独立答案/验证器的低风险任务，用真实非LLM专业工具 + 至少一个语言模型做一次有预算会诊，与单模型/单工具基线对照。能否接入现有本地服务应先只读发现并另行确认，不借立项自动消耗任何账户额度。

模型建议仅供用户手动选择：架构/共识/经济边界用当前高能力模型或 Sol；规格冻结后的适配器和回归测试可交 Luna。此建议不是执行门槛，系统不自动切换模型。
